# 对位猜数字 · 双人在线对战

移动端优先的双人实时网页小游戏。前端位于 `public/index.html`；房间、玩家身份、模式、密码、骰子、回合、命中数、胜负与尊严之战均由 Node.js + Socket.IO 服务端控制。

## 本地运行

```bash
npm ci
npm start
```

打开 `http://localhost:3000`。同一局域网内的手机可访问运行电脑的局域网 IP 和端口进行测试。请勿用 `file://` 直接打开 HTML；实时对战需要连接 Node.js 服务。

## 对局流程

1. 输入昵称（1–4 个汉字、英文字母或数字；可留空使用默认昵称），创建房间或用 4–6 位字母数字房间号加入。
2. 房主在准备阶段选择 3 位或 4 位模式，选择后本局锁定。
3. 双方分别设置并锁定自己的密码（0–9，可重复、可 0 开头）。双方都锁定后才能掷骰。
4. 双方各掷一次骰子，点数大的一方先猜；同点重掷。
5. 轮流提交完整猜测。服务端只反馈「猜对 X 个」，只计数字与位置同时正确的位数，不提示位置。
6. 一方全部猜中后进入结算。败方可发起尊严之战；获胜方同意后，败方最多猜两次，任一次全部命中则本局平局。
7. 结算阶段公布双方密码。双方都点击「再来一局」后保留房间与比分，清空对局数据；房主重新选模式。

## 房间与断线

- 新房间码为 6 位不易混淆的字母数字组合，最多 2 人；第三人会收到中文提示。
- 房间链接格式为 `https://你的域名/?room=房间号`；打开链接可自动尝试加入。
- 玩家断线后保留座位 90 秒，期间刷新可凭浏览器本地的重连令牌恢复；断线期间暂停对局。
- 房间无人在线 30 分钟后清理。房间状态保存在进程内存，服务重启会清空；适用于单实例部署。
- 尊严之战同意请求等待 30 秒，超时视为拒绝并进入最终结算。

## 公网部署（Render）

仓库根目录包含 `render.yaml`。将项目推送至 GitHub 后，在 Render 使用 **New → Blueprint** 连接仓库并部署；服务会监听 Render 提供的 `PORT`，并提供 `/healthz` 健康检查。部署成功后使用 Render 的 HTTPS 服务地址，玩家可在手机和电脑上打开同一个房间链接。

免费实例可能休眠；服务进程重启后，内存中的房间会消失。需要持久房间时，应改用 Redis 等外部存储。

## 技术栈与检查

- Node.js、Express、Socket.IO；网页通过同源 Socket.IO 连接实时同步。
- 输入在前后端双重校验；前端不计算命中、比分或胜负。
- `npm run check` 检查服务端及内联浏览器脚本语法。
